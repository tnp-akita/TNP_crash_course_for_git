# 用語
---

- リポジトリ - ファイル置き場、作業環境のこと。
    - リモートリポジトリ - GitHub 上のリポジトリのこと
    - ローカルリポジトリ - あなたのPC上のリポジトリのこと。リモートリポジトリの複製を保存するだけで、自動的には同期されない。同期には「フェッチ」「プル」を使う。
- `origin` - ここでは GitHub 上で管理されているリモートリポジトリのこと。
- ステージ(されたファイル) - `git add` でコミットの準備がされたファイルのこと。
- ステージング - `git add` でコミットされるファイルを追加すること。
- コミット (commit) - `git commit` で、リポジトリにステージングされたフォルダやファイルを書き込むこと。 (作業中のPCにしか保存されない)
- ブランチ (branch) - リポジトリの中の「次元」のようなもの。リポジトリ内のフォルダやファイルはブランチごとに管理され、ブランチを切り替える(**チェックアウト**する)とファイルの中身は引き継がれない。ブランチ同士は「マージ」によって結合できる。
- チェックアウト (checkout) - `git checkout` でブランチを切り替えること。
- フェッチ (fetch) - リモートリポジトリの変更を、ローカルリポジトリの「`origin/`」以下のブランチに取り込むこと。あなたの作業内容を上書きする必要なく、ほかの人の行った変更を見ることができる。
- プル (pull) - リモートリポジトリの変更を、リモートリポジトリの同じ名前のブランチに取り込むこと。あなたの作業内容は統合(マージ)されるので、pull する前には変更をコミットするか、スタッシュして一時的に退避しなければならない。
- マージ (merge) - ブランチ同士を統合すること。たとえばあなたが「`develop`」というブランチで作業した内容を「`main`」というブランチに反映したいなら、「`develop` を `main` にマージする」作業を行う。
- コンフリクト (conflict) - マージするときに変更が競合、バッティングすること。同じファイルの同じ関数をいじるなど、変更が矛盾するときにはコンフリクトが「発生」するという。これらを「解消」することでマージが可能になる。
- スタッシュ (stash) - 作業内容を一時的に退避・保存すること。コミットと違いあなた専用の退避場所が作られるので、変更をスタッシュすることで、コミットせずとも「プル」が実行できる。
- master & slave - master ブランチとその子ブランチのこと。
